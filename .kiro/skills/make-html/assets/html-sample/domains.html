Coupling Hotspotsจุดผูกกันสูง

Highserver/modules/jobsh.js — Orchestratorตัวประสานงาน

Imports and directly calls functions from 7 other modules (careProvider, assistanceDentist, service, careProviderService, patientAppointment, doctorSchedule, healthCheck). This central coordination point must become an event-driven or saga-based coordinator when domains split.นำเข้าและเรียกฟังก์ชันจากอีก 7 โมดูลโดยตรง (careProvider, assistanceDentist, service, careProviderService, patientAppointment, doctorSchedule, healthCheck) จุดประสานงานกลางนี้ต้องเปลี่ยนเป็นการประสานแบบ event-driven หรือ saga เมื่อแยกโดเมน

Highserver/event-bridge.js — Multi-Domain Writerตัวเขียนข้ามโดเมน

Writes directly to tables owned by two domains — RoomDetail (room-management) and PatientAppointment (patient-appointment). Must be split into domain-specific event handlers or use inter-service API calls.เขียนข้อมูลลงตารางที่เป็นของสองโดเมนโดยตรง — RoomDetail (room-management) และ PatientAppointment (patient-appointment) ต้องแยกเป็น event handler เฉพาะโดเมนหรือเรียก API ระหว่างบริการ

HighdoctorSchedule.js — Workload Queryคิวรีคำนวณภาระงาน

The workload CTE joins 4 tables across 3 domains (DoctorSchedule, RoomDetail, PatientAppointment, Service) in one query. Requires a materialized view, data replication, or a dedicated reporting service after decomposition.คิวรี CTE คำนวณภาระงาน join 4 ตารางจาก 3 โดเมน (DoctorSchedule, RoomDetail, PatientAppointment, Service) ในคิวรีเดียว หลังแยกระบบต้องใช้ materialized view, การจำลองข้อมูล หรือบริการรายงานเฉพาะ

Mediumsrc/routes/index.js — Frontend data hubศูนย์รวมข้อมูลฝั่งหน้าเว็บ

Fetches data from all 5 domains and passes it down as props — the single data-loading point for the entire frontend. In a microservices architecture this becomes a BFF (Backend-for-Frontend) or API gateway.ดึงข้อมูลจากทั้ง 5 โดเมนแล้วส่งต่อเป็น props เป็นจุดโหลดข้อมูลจุดเดียวของทั้งหน้าเว็บ ในสถาปัตยกรรมไมโครเซอร์วิสจะกลายเป็น BFF (Backend-for-Frontend) หรือ API gateway

Resolutionแนวทางแก้

patient-appointment and doctor-schedule reference each other for workload calculation. Break the cycle by extracting workload into a dedicated read-model (materialized view or a small analytics service) that consumes events from both contexts, so neither service calls the other synchronously.patient-appointment และ doctor-schedule อ้างอิงกันเพื่อคำนวณภาระงาน แก้วงจรด้วยการแยกการคำนวณภาระงานออกเป็น read-model เฉพาะ (materialized view หรือบริการวิเคราะห์ขนาดเล็ก) ที่รับ event จากทั้งสองบริบท เพื่อไม่ให้บริการใดเรียกกันแบบ synchronous

Key Notes (server perspective)หมายเหตุสำคัญ (จากมุมมอง server)

dental_db — single shared databaseฐานข้อมูลร่วมชุดเดียว

One PostgreSQL instance holds all 13 tables for all 5 domains with no schema isolation. This is the single largest obstacle to independent deployment.PostgreSQL อินสแตนซ์เดียวเก็บทั้ง 13 ตารางของทั้ง 5 โดเมนโดยไม่มีการแยก schema เป็นอุปสรรคใหญ่ที่สุดต่อการ deploy อิสระ

event-bridge.js

A single fork-mode process is the only writer for OPD-sourced room and patient-status events, writing across two domains' tables.โปรเซส fork เดียวเป็นตัวเขียนเพียงตัวเดียวสำหรับ event ห้องและสถานะผู้ป่วยจาก OPD โดยเขียนข้ามตารางของสองโดเมน

scheduler.js

Cron process is the only writer for TrakCare-sourced master data and appointments; other services read the results from cache/DB.โปรเซส cron เป็นตัวเขียนเพียงตัวเดียวสำหรับ master data และนัดหมายจาก TrakCare บริการอื่นอ่านผลลัพธ์จากแคช/ฐานข้อมูล

in-memory cache

Each module keeps process-local arrays refreshed on a 60s interval and on events. PM2 cluster mode means each worker has an independent, potentially divergent cache.แต่ละโมดูลเก็บ array ในหน่วยความจำของโปรเซส รีเฟรชทุก 60 วินาทีและเมื่อมี event โหมด cluster ของ PM2 ทำให้แต่ละ worker มีแคชแยกกันและอาจไม่ตรงกัน

Target: dedicated data storesเป้าหมาย: ฐานข้อมูลเฉพาะบริการ

After extraction, each service should own its schema/database, with care-provider master data exposed via API or replicated read-models rather than shared tables.หลังการแยก แต่ละบริการควรเป็นเจ้าของ schema/ฐานข้อมูลของตัวเอง โดยเปิดเผยข้อมูลหลัก care-provider ผ่าน API หรือ read-model ที่จำลองไว้แทนการใช้ตารางร่วม

Security & resilienceความปลอดภัย & ความทนทาน

Single DB with no replica is a SPOF; TLS verification to TrakCare is disabled; credentials sit in plaintext .env files. Address these before or alongside decomposition.ฐานข้อมูลชุดเดียวไม่มี replica เป็น SPOF การตรวจสอบ TLS ไปยัง TrakCare ถูกปิด และข้อมูลรับรองอยู่ในไฟล์ .env แบบข้อความธรรมดา ควรแก้ก่อนหรือระหว่างการ decomposition
