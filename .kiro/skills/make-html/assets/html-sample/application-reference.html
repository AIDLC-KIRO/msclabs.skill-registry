Runtime Configuration Referenceคู่มืออ้างอิงการตั้งค่ารันไทม์

All runtime settings come from dotenv files selected by NODE_ENV — .env, .env.development, .env.production and .env.test share an identical key set with different values. There is no secrets manager and no encryption at rest.ค่าตั้งรันไทม์ทั้งหมดมาจากไฟล์ dotenv ที่เลือกด้วย NODE_ENV — .env, .env.development, .env.production และ .env.test ใช้ชุดคีย์เดียวกันแต่ค่าต่างกัน ไม่มีระบบจัดการความลับและไม่มีการเข้ารหัสข้อมูลที่จัดเก็บ

Security findings in configuration. .env.production is present in the working tree and carries the database password, the shared API key and TrakCare service credentials. The Event Bridge sets NODE_TLS_REJECT_UNAUTHORIZED = "0", disabling TLS certificate validation for every outbound HTTPS call, and app.set("trust proxy", () => true) trusts all proxies so X-Forwarded-For can be spoofed to bypass rate limiting. CORS is origin: "*" and ENABLE_API_KEY is false in all four env files.ประเด็นความปลอดภัยในไฟล์ตั้งค่า ไฟล์ .env.production อยู่ใน working tree และมีรหัสผ่านฐานข้อมูล API key ที่ใช้ร่วมกัน และบัญชีบริการของ TrakCare — Event Bridge ตั้งค่า NODE_TLS_REJECT_UNAUTHORIZED = "0" ซึ่งปิดการตรวจใบรับรอง TLS ของทุกการเรียก HTTPS ออกภายนอก และ app.set("trust proxy", () => true) เชื่อถือ proxy ทุกตัวจนสามารถปลอม X-Forwarded-For เพื่อเลี่ยง rate limit ได้ นอกจากนี้ CORS ตั้งเป็น origin: "*" และ ENABLE_API_KEY เป็น false ในไฟล์ env ทั้งสี่ไฟล์

Runtime Settings & Notable Flagsการตั้งค่ารันไทม์และแฟล็กที่ควรทราบ

NODE_TLS_REJECT_UNAUTHORIZED "0"

Set at the top of server/event-bridge.js. Disables TLS certificate validation for every outbound HTTPS call from that process — likely a workaround for a self-signed certificate on the internal TrakCare server. Rated high risk.ตั้งไว้ที่ต้นไฟล์ server/event-bridge.js ปิดการตรวจใบรับรอง TLS ของทุกการเรียก HTTPS ออกจากโปรเซสนี้ — น่าจะเป็นวิธีเลี่ยงปัญหาใบรับรอง self-signed ของเซิร์ฟเวอร์ TrakCare ภายใน จัดเป็นความเสี่ยงสูง

trust proxy (ip) => true

Event Bridge trusts every proxy, so a spoofed X-Forwarded-For header can bypass the per-IP rate limiter. The body parser also has no size limit, leaving large-payload DoS open.Event Bridge เชื่อถือ proxy ทุกตัว จึงสามารถปลอม header X-Forwarded-For เพื่อเลี่ยง rate limit ต่อ IP ได้ และ body parser ยังไม่จำกัดขนาด payload ทำให้เสี่ยง DoS จาก payload ขนาดใหญ่

CORS origin "*"

Set in server/middlewares/index.js for the App Service; the Event Bridge falls back to "*" when ALLOWED_ORIGINS is unset. Any domain can call the API.ตั้งใน server/middlewares/index.js สำหรับ App Service และ Event Bridge จะกลับไปใช้ "*" เมื่อไม่ได้ตั้ง ALLOWED_ORIGINS ทำให้โดเมนใดก็เรียก API ได้

ENABLE_API_KEY false

The x-api-key middleware and IP filter both exist in server/app.js, but the key check is switched off in all four env files — the API is effectively open on the internal network.มี middleware ตรวจ x-api-key และตัวกรอง IP อยู่ใน server/app.js แต่การตรวจคีย์ถูกปิดในไฟล์ env ทั้งสี่ไฟล์ — API จึงเปิดโล่งในเครือข่ายภายใน

Rate limiting 1000 req/s per IP

Event Bridge limit via express-rate-limit with a custom key generator that normalises IPv6 loopback. The App Service applies its own limiter plus Helmet security headers.Event Bridge จำกัดผ่าน express-rate-limit พร้อม key generator ที่แปลง loopback แบบ IPv6 ให้เป็นรูปแบบเดียวกัน ส่วน App Service มี limiter ของตัวเองและ header ความปลอดภัยจาก Helmet

PM2 exec_mode cluster / fork

app-service runs in cluster mode with instances: 'max'; event-bridge-service and scheduler-service are single-instance fork mode. All three restart automatically after 5000 ms.app-service รันโหมด cluster ด้วย instances: 'max' ส่วน event-bridge-service และ scheduler-service รันโหมด fork แบบอินสแตนซ์เดียว ทั้งสามตัวรีสตาร์ตเองหลัง 5000 ms

Log rotation 10M · retain 30

PM2 logrotate compresses and rotates daily at midnight, keeping 30 days; the scheduler separately purges files older than LOG_RETENTION_DAYS = 90.PM2 logrotate บีบอัดและหมุนไฟล์ทุกเที่ยงคืน เก็บย้อนหลัง 30 วัน ขณะที่ scheduler ลบไฟล์ที่เก่ากว่า LOG_RETENTION_DAYS = 90 แยกอีกชั้น

Sync window 06:00–22:00 · every 60 s

Appointment sync is guarded by an hour check in jobsh.taskIntervalGetDataFromTrakcare and skipped outside clinic hours. Master data refreshes daily at 00:01; doctor schedules at 07:30, 11:30 and 16:30.การซิงก์นัดหมายมีการตรวจชั่วโมงใน jobsh.taskIntervalGetDataFromTrakcare และจะข้ามเมื่ออยู่นอกเวลาทำการ — master data รีเฟรชทุกวันเวลา 00:01 และตารางแพทย์รีเฟรชที่ 07:30, 11:30 และ 16:30

Six documented flows drive the system: startup master-data load, real-time patient status, room login/logout, the 60-second appointment sync, frontend refresh, and the 00:01 daily maintenance job. The three below are the ones a migration must reproduce exactly.ระบบขับเคลื่อนด้วยกระแสงาน 6 ชุดตามเอกสาร: โหลด master data ตอนสตาร์ต, สถานะผู้ป่วยแบบเรียลไทม์, การเข้า/ออกห้องของแพทย์, การซิงก์นัดหมายทุก 60 วินาที, การรีเฟรชฝั่งหน้าเว็บ และงานบำรุงรักษารายวันเวลา 00:01 — สามกระแสงานด้านล่างคือชุดที่การย้ายระบบต้องทำซ้ำให้ตรงทุกขั้น

Business Rules Highlightsสรุปกฎทางธุรกิจสำคัญ

Concrete rules a developer must preserve when refactoring or migrating.กฎรูปธรรมที่นักพัฒนาต้องรักษาไว้เมื่อ refactor หรือย้ายระบบ

Status priority orderingลำดับความสำคัญของสถานะ

A single SQL CASE decides the displayed status in this exact order: PT_Status P → Processing, H → Hold, E → End Service, then PAADM_VisitStatus = 'C' → Canceled, then no arrival and no cancel → Booked, then arrival present → Arrived, then cancel present → Canceled. Event-driven statuses always win over TrakCare arrival data.คำสั่ง SQL CASE ชุดเดียวกำหนดสถานะที่แสดงตามลำดับนี้เท่านั้น: PT_Status P → Processing, H → Hold, E → End Service จากนั้น PAADM_VisitStatus = 'C' → Canceled ถัดมาไม่มีเวลามาถึงและไม่มีการยกเลิก → Booked แล้วมีเวลามาถึง → Arrived และมีการยกเลิก → Canceled โดยสถานะที่มาจากอีเวนต์จะชนะข้อมูลการมาถึงจาก TrakCare เสมอ

One doctor per room, one room per doctorหนึ่งแพทย์ต่อหนึ่งห้อง และหนึ่งห้องต่อหนึ่งแพทย์

On login the Event Bridge first flips every 'In' row matching the target Room or the same CarpCode to 'Out' with a LogoutTime, then inserts the new row. The invariant is enforced by that double update, not by a database constraint.เมื่อแพทย์เข้าห้อง Event Bridge จะเปลี่ยนทุกแถวที่มีสถานะ 'In' ซึ่งตรงกับ Room เป้าหมาย หรือ CarpCode เดียวกันให้เป็น 'Out' พร้อมบันทึก LogoutTime ก่อน แล้วจึงแทรกแถวใหม่ — เงื่อนไขนี้บังคับด้วยการอัปเดตสองชั้น ไม่ใช่ด้วย constraint ของฐานข้อมูล

Patient call guardเงื่อนไขป้องกันการเรียกซ้ำ

A patient may only move to Processing when PT_Status NOT IN ('P','H','E') and APPT_CancelDate IS NULL and PAADM_VisitStatus != 'C' and the CarpCode matches the doctor currently in that room. This prevents re-calling a patient already being served.ผู้ป่วยจะเปลี่ยนเป็น Processing ได้เมื่อ PT_Status NOT IN ('P','H','E') และ APPT_CancelDate IS NULL และ PAADM_VisitStatus != 'C' และ CarpCode ตรงกับแพทย์ที่อยู่ในห้องนั้นขณะนั้น เพื่อไม่ให้เรียกผู้ป่วยที่กำลังรับบริการอยู่แล้วซ้ำ

10-minute waiting alertการแจ้งเตือนรอเกิน 10 นาที

returnBlinkPatient takes each Arrived patient, adds 10 minutes to the appointment time, and once the clock passes that threshold scans the same doctor's later appointments. If none is Processing, the room gets a blink CSS class.returnBlinkPatient จะนำผู้ป่วยที่สถานะ Arrived แต่ละราย บวกเวลานัด 10 นาที และเมื่อเลยเวลานั้นแล้วจะไล่ดูนัดถัดไปของแพทย์คนเดียวกัน หากไม่พบนัดที่เป็น Processing ห้องนั้นจะได้คลาส CSS ให้กะพริบ

Walk-in minute filterตัวกรองนาทีของผู้ป่วย walk-in

Appointments whose minute component is "04", "07" or "09" are excluded from the alarm scan — those minute values are used as walk-in markers rather than real appointment times.นัดที่ส่วนนาทีเป็น "04", "07" หรือ "09" จะถูกตัดออกจากการตรวจแจ้งเตือน เพราะค่านาทีเหล่านี้ใช้เป็นเครื่องหมายของผู้ป่วย walk-in ไม่ใช่เวลานัดจริง

Care provider display filterตัวกรองการแสดงแพทย์บนหน้าจอ

A doctor appears on the dashboard when SUMSLOT != null or there are no canceled appointments or there are both canceled and non-canceled ones — and always requires at least one appointment. A doctor holding only canceled appointments with no schedule slot is hidden.แพทย์จะปรากฏบนแดชบอร์ดเมื่อ SUMSLOT != null หรือ ไม่มีนัดที่ถูกยกเลิก หรือ มีทั้งนัดที่ยกเลิกและไม่ยกเลิก และต้องมีนัดอย่างน้อยหนึ่งรายการเสมอ — แพทย์ที่มีเฉพาะนัดที่ถูกยกเลิกและไม่มีช่วงเวรจะถูกซ่อน

Clinic-hours sync windowช่วงเวลาซิงก์ตามเวลาทำการ

Appointment sync runs every 60 seconds but only when the current hour is between 6 and 22 inclusive. Outside that window the task returns immediately and the cache keeps its last value.การซิงก์นัดหมายทำงานทุก 60 วินาที แต่เฉพาะเมื่อชั่วโมงปัจจุบันอยู่ระหว่าง 6 ถึง 22 เท่านั้น หากอยู่นอกช่วงนี้งานจะคืนค่าทันทีและแคชยังคงค่าล่าสุดไว้

Daily archive at 00:01การเก็บประวัติรายวันเวลา 00:01

Current appointments are copied to PatientAppointmentHistory, PatientAppointment is emptied, master data and doctor schedules are re-fetched for the current and next month, memory is reloaded, and log files older than 90 days are purged.คัดลอกนัดหมายปัจจุบันไปยัง PatientAppointmentHistory ล้าง PatientAppointment ดึง master data และตารางเวรแพทย์ของเดือนนี้กับเดือนถัดไปใหม่ โหลดข้อมูลเข้าหน่วยความจำอีกครั้ง และลบไฟล์ล็อกที่เก่ากว่า 90 วัน

Initial status mapping on importการกำหนดสถานะเริ่มต้นตอนนำเข้า

getAppointment assigns C when PAADM_VisitStatus == "C", else A when APPT_ArrivalDate != "", else C when APPT_CancelDate != "", else B. Note the empty-string comparisons rather than null checks — a behaviour the migration must copy verbatim.getAppointment กำหนดค่า C เมื่อ PAADM_VisitStatus == "C" ถัดมาเป็น A เมื่อ APPT_ArrivalDate != "" ถัดมาเป็น C เมื่อ APPT_CancelDate != "" และค่าอื่นเป็น B — สังเกตว่าเป็นการเทียบกับสตริงว่าง ไม่ใช่การตรวจ null ซึ่งเป็นพฤติกรรมที่การย้ายระบบต้องคัดลอกให้ตรงทุกตัวอักษร

Event deduplicationการกันอีเวนต์ซ้ำ

The Event Bridge hashes each incoming object with object-hash and compares against previousRoomDetailHash / previousPatientStatusHash. Identical payloads are silently dropped, so duplicate OPD posts never trigger a broadcast.Event Bridge จะแฮชอ็อบเจกต์ที่เข้ามาด้วย object-hash แล้วเทียบกับ previousRoomDetailHash / previousPatientStatusHash — payload ที่เหมือนกันจะถูกทิ้งเงียบ ๆ ทำให้การ POST ซ้ำจาก OPD ไม่กระจายอีเวนต์

Room booking shapeโครงสร้างการจองห้อง

A booking carries one doctor, up to two assistants (AssistCode1, AssistCode2), a room, a day of week, a start/end date range, a start/end time range and a work case.การจองหนึ่งรายการประกอบด้วยแพทย์หนึ่งคน ผู้ช่วยได้ถึงสองคน (AssistCode1, AssistCode2) ห้องหนึ่งห้อง วันในสัปดาห์ ช่วงวันที่เริ่ม/สิ้นสุด ช่วงเวลาเริ่ม/สิ้นสุด และประเภทงาน

Render-skip optimisationการข้ามการเรนเดอร์

shouldComponentUpdate re-renders on #/ and any #/dashboard* route but deliberately blocks re-renders on #/schedule and #/calendar, so 6-second polling does not disturb those views.shouldComponentUpdate จะเรนเดอร์ใหม่เมื่ออยู่ที่ #/ และเส้นทาง #/dashboard* แต่ตั้งใจบล็อกการเรนเดอร์ซ้ำที่ #/schedule และ #/calendar เพื่อไม่ให้การ poll ทุก 6 วินาทีรบกวนสองมุมมองนั้น

Rules are drawn from server/modules/patientAppointment.js, server/event-bridge.js, server/modules/jobsh.js and src/routes/index.js. Behaviour documentation in the ATX report is marked early access — validate each rule against the source before relying on it for a rewrite.กฎเหล่านี้สกัดจาก server/modules/patientAppointment.js, server/event-bridge.js, server/modules/jobsh.js และ src/routes/index.js — เอกสารส่วนพฤติกรรมในรายงาน ATX ระบุว่าเป็น early access จึงควรตรวจสอบแต่ละกฎกับซอร์สโค้ดก่อนนำไปใช้เขียนระบบใหม่

External Integrations & Dependenciesการเชื่อมต่อภายนอกและ Dependency

TrakCare HIS (InterSystems)

System of record for patients, appointments, care providers, services and doctor schedules. OAuth2 bearer token from POST /api/iam/login, then seven GET /api/PTINF/* endpoints scoped to location 01DEN. Also the only authentication authority — POST /logonTrakcare delegates user login. No request timeout is configured on the axios calls and there is no circuit breaker.เป็นแหล่งข้อมูลหลักของผู้ป่วย นัดหมาย แพทย์ผู้ให้บริการ บริการ และตารางเวรแพทย์ ขอ bearer token แบบ OAuth2 จาก POST /api/iam/login แล้วเรียก GET /api/PTINF/* เจ็ดเส้นทางโดยจำกัดที่หน่วยงาน 01DEN และยังเป็นผู้ยืนยันตัวตนรายเดียว — POST /logonTrakcare ส่งการเข้าสู่ระบบของผู้ใช้ต่อไปให้ TrakCare โดยการเรียกผ่าน axios ไม่ได้ตั้ง timeout และไม่มี circuit breaker

OPD Queue · Patient Flow

Pushes room login/logout and patient lifecycle events into the Event Bridge with two unauthenticated POST calls on port 8080. The bridge writes state to PostgreSQL and fans the change out over Socket.IO to the App Service and every browser. Six event names in total, deduplicated with object-hash.ส่งอีเวนต์การเข้า/ออกห้องของแพทย์และสถานะผู้ป่วยเข้ามาที่ Event Bridge ผ่าน POST สองเส้นทางบนพอร์ต 8080 ที่ไม่มีการยืนยันตัวตน — Event Bridge จะเขียนสถานะลง PostgreSQL แล้วกระจายผ่าน Socket.IO ไปยัง App Service และเบราว์เซอร์ทุกเครื่อง รวมทั้งหมด 6 ชื่ออีเวนต์ พร้อมกันซ้ำด้วย object-hash

PostgreSQL 14.2 · dental_db

Single database on db-host:5432, reached through one pg 8.7.3 pool capped at 20 connections. 13 tables, no ORM, no migration tool — schema history lives in dental-db-20241224.sql and CreateIndexKey-1.sql.ฐานข้อมูลชุดเดียวที่ db-host:5432 เข้าถึงผ่าน pool ของ pg 8.7.3 ที่จำกัด 20 connection มี 13 ตาราง ไม่มี ORM และไม่มีเครื่องมือ migration — ประวัติสคีมาอยู่ในไฟล์ dental-db-20241224.sql และ CreateIndexKey-1.sql
