Priority 1

Critical Security Fixesแก้ไขความปลอดภัยที่สำคัญ

Quick Winsทำได้เร็ว
1.1 Remove the TLS certificate bypass in server/event-bridge.js and install the proper CA chain for TrakCare — coordinate with infrastructure first, since a self-signed certificate will otherwise break the connection.ลบการข้ามตรวจใบรับรอง TLS ใน server/event-bridge.js และติดตั้งใบรับรอง CA ที่ถูกต้องสำหรับ TrakCare โดยต้องประสานกับทีมโครงสร้างพื้นฐานก่อน เพราะหากใบรับรองเป็นแบบ self-signed การเชื่อมต่อจะล้มเหลว
1.2 Replace origin: "*" in server/middlewares/index.js with the specific frontend domain from an environment variable.เปลี่ยน origin: "*" ใน server/middlewares/index.js ให้เป็นโดเมนของหน้าเว็บที่ระบุผ่านตัวแปรสภาพแวดล้อม
1.3 Upgrade axios from 0.19.2 to 1.7.x and adjust the .data access and FormData usage that changes with it.อัปเกรด axios จาก 0.19.2 เป็น 1.7.x และปรับการเข้าถึง .data กับการใช้ FormData ที่เปลี่ยนไปตามเวอร์ชัน
1.4 Replace the blanket trust proxy return value with an explicit list of trusted proxy IPs so rate limiting identifies real client addresses.เปลี่ยนค่า trust proxy ที่คืนค่าเชื่อถือทุกตัว ให้เป็นรายการ IP ของ proxy ที่เชื่อถือได้อย่างชัดเจน เพื่อให้การจำกัดอัตราระบุ IP ของไคลเอนต์จริงได้
Priority 2

Frontend Modernizationปรับปรุงฝั่งหน้าเว็บให้ทันสมัย

SprintSprint
2.1 Migrate the build from Create React App to Vite — add @vitejs/plugin-react, move public/index.html to the root, rewrite the npm scripts and drop react-scripts. This clears the Webpack 4 debt in one step.ย้ายระบบ build จาก Create React App ไปเป็น Vite โดยเพิ่ม @vitejs/plugin-react ย้าย public/index.html ไปไว้ที่ราก เขียนสคริปต์ npm ใหม่ และถอด react-scripts ออก ซึ่งจะลบหนี้จาก Webpack 4 ได้ในขั้นตอนเดียว
2.2 Upgrade React 16 to 18 and Material UI 4 to MUI 5 — swap ReactDOM.render for createRoot, run the MUI v5 codemods, and replace Enzyme with React Testing Library. Vite must land first, since CRA 3 cannot run React 18.อัปเกรด React 16 เป็น 18 และ Material UI 4 เป็น MUI 5 โดยเปลี่ยน ReactDOM.render เป็น createRoot รัน codemod ของ MUI v5 และเปลี่ยนจาก Enzyme ไปใช้ React Testing Library ทั้งนี้ต้องย้ายไป Vite ให้เสร็จก่อน เพราะ CRA 3 ไม่รองรับ React 18

Architectural Improvementsปรับปรุงเชิงสถาปัตยกรรม

ProgramProgram
4.1 Break up the god component — move data fetching, the WebSocket subscription and the alarm calculation into custom hooks, and hold shared state in Context or Zustand.แยก god component ออก โดยย้ายการดึงข้อมูล การ subscribe WebSocket และการคำนวณการแจ้งเตือนไปเป็น custom hook และเก็บสถานะที่ใช้ร่วมกันไว้ใน Context หรือ Zustand
4.2 Delete the dead code — the whole server/modules.old/ tree, every .old duplicate and the commented-out blocks, roughly 2,500 lines in total.ลบโค้ดที่ไม่ใช้ทั้งหมด ทั้งไดเรกทอรี server/modules.old/ ไฟล์ .old ทุกไฟล์ และโค้ดที่คอมเมนต์ทิ้งไว้ รวมประมาณ 2,500 บรรทัด
4.3 Add real test coverage — unit tests for the patientAppointment business rules, integration tests for the 19 endpoints, and component tests for the blink and alarm logic.เพิ่มการทดสอบให้ครอบคลุมจริง ทั้งการทดสอบหน่วยสำหรับกฎธุรกิจใน patientAppointment การทดสอบการเชื่อมต่อของ endpoint ทั้ง 19 เส้นทาง และการทดสอบคอมโพเนนต์สำหรับตรรกะไฟกะพริบและการแจ้งเตือน
4.4 Extract the SQL layer — move queries out of template literals, centralize the status-mapping CASE, and add migration tooling such as knex.แยกชั้น SQL ออกมา โดยย้ายคิวรีออกจาก template literal รวมศูนย์ CASE ที่แปลงสถานะ และเพิ่มเครื่องมือ migration เช่น knex
